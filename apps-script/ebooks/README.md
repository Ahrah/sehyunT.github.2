# 전자책 9권 계좌이체 판매: 구글 시트 + Apps Script

홈페이지 `/ebooks/` 주문서가 Apps Script 웹 앱으로 주문을 보냅니다. **모의면접과 같은 시트, 같은 Apps Script 프로젝트**에 파일 하나(`Ebook.gs`)를 더 넣는 방식입니다.
웹 앱 주소도 모의면접과 같습니다.

- `전자책 주문` 탭: 주문 1건이 1줄입니다.
- `전자책 발송 기록` 탭: PDF 메일을 보낼 때마다 1줄(성공·실패, 다시 보냄 포함).
- `현금영수증 발급 대기` 탭: 현금영수증 번호를 적은 주문이 PDF 발송 뒤 여기에 쌓입니다. 발급하면 `발급함`을 체크합니다.
- `입금알림 기록` 탭: (선택 기능을 켰을 때) 읽은 입금 알림 메일. 모의면접과 같이 씁니다.

PDF는 세연쌤 구글 드라이브에만 둡니다. 홈페이지와 저장소에는 올리지 않습니다.

## 1. 처음 한 번 설정하기 (약 15분)

모의면접 Apps Script를 이미 설치했다고 가정합니다(`../mock-interview/README.md` 1번). 아직이면 그것부터 합니다.

1. **PDF를 드라이브에 올립니다.** 세연쌤 구글 드라이브에 폴더(예: `전자책 원본`)를 만들고 PDF 9개를 올립니다. 폴더와 파일은 **공유하지 않습니다**(링크 공유도 끔).
2. **파일 ID를 복사합니다.** 파일을 하나씩 열고 **공유 → 링크 복사**를 누르면 `https://drive.google.com/file/d/여기가_ID/view...`가 복사됩니다. `/d/`와 `/view` 사이가 파일 ID입니다.
3. Apps Script 편집기에서 **파일 + → 스크립트**를 누르고 이름을 `Ebook`으로 만듭니다. 이 폴더의 `Ebook.gs`를 통째로 붙여 넣습니다.
4. `Ebook.gs` 위쪽 `EB.BOOKS`에서 책마다 `fileId`를 고칩니다.
   - `fileId: 'PDF_파일_ID_01_비교자료집'` → `fileId: '복사한 ID'`
   - 가격은 이미 들어 있습니다(11/3 결정, 11/3 21:48 변경): 학교별 가이드 `price: 15000`, 비교 자료집 `price: 79000`.
   - 묶음 가격은 없습니다. 9권(학교별 가이드 8권 + 비교 자료집)을 모두 골라도 낱권 합계(199,000원)로 받습니다.
   - 아래 표의 파일과 짝을 맞춥니다.

   | id | 책 | PDF 파일 |

   | compare | 입시는세연쌤books 2027 경기권 외고 8개교 비교 자료집 | 01_비교자료집.pdf |
   | gyeonggi | 입시는세연쌤books 2027 경기외고 자소서·면접 가이드 | 02_경기외고.pdf |
   | goyang | 입시는세연쌤books 2027 고양외고 자소서·면접 가이드 | 03_고양외고.pdf |
   | gwacheon | 입시는세연쌤books 2027 과천외고 자소서·면접 가이드 | 04_과천외고.pdf |
   | gimpo | 입시는세연쌤books 2027 김포외고 자소서·면접 가이드 | 05_김포외고.pdf |
   | dongducheon | 입시는세연쌤books 2027 동두천외고 자소서·면접 가이드 | 06_동두천외고.pdf |

   판매 페이지 제목은 위 표의 '입시는세연쌤books 2027 …'입니다. PDF 파일명은 그대로 둡니다.

   가격을 바꾸면 홈페이지 코드 `src/lib/ebooks.ts`의 `price`도 같은 값으로 바꿔야 합니다(개발 쪽에서 함께 고칩니다. `npm test`가 두 파일이 같은지 봅니다). 묶음 가격은 쓰지 않습니다.
   판매는 9권을 한 번에 엽니다(문장 수정과 Bot1 검증이 끝난 뒤 웹 앱 주소를 홈페이지에 넣는 날).
5. `Code.gs`와 `appsscript.json`도 이 브랜치의 `../mock-interview/` 파일로 바꿉니다(전자책 연결 몇 줄과 드라이브 보기 권한이 추가됐습니다).
6. 저장한 뒤 함수 목록에서 `setup`을 고르고 **실행**합니다. 권한 창에서 **구글 드라이브 파일 보기**가 새로 보이면 허용합니다.
   - 실행이 끝나면 `전자책 주문`, `전자책 발송 기록`, `현금영수증 발급 대기` 탭이 생깁니다.
   - `전자책 주문` 탭을 이미 만들었다면 `setup`을 한 번 더 실행합니다. 맨 뒤에 `입금 기한` 칸이 붙습니다(기존 칸 이름·순서는 그대로).
7. **배포 → 배포 관리 → 수정(연필) → 버전: 새 버전 → 배포**를 누릅니다. 웹 앱 URL은 그대로입니다.
8. 같은 웹 앱 URL을 홈페이지 빌드 값 `VITE_EBOOKS_API_URL`에도 넣습니다(GitHub 저장소 Settings → Secrets and variables → Actions → Variables). 채팅·문서에는 붙이지 않습니다.
9. **시험 주문 1건**: 실제 홈페이지 `/ebooks/`에서 세연쌤 다른 메일 주소로 1권 주문 → `전자책 주문` 탭에 줄이 생기는지 봅니다 → `입금 확정` 체크 → 1~2분 안에 PDF 메일이 오는지 봅니다 → 그 줄의 `취소`를 체크하거나 줄을 지웁니다.

## 2. 입금 확인

### 2-1. 주문 접수(입금 안내) 메일

주문이 들어오면 바로 주문자에게 `[입시는세연쌤] 전자책 주문 입금 안내 (주문번호)` 메일이 나갑니다.
메일에는 주문번호, 고른 책, 은행(카카오뱅크)·계좌번호(3333-38-6269721)·예금주(입시는세연쌤), 금액, 입금자명(이름+숫자 2자리), 입금 기한(주문 뒤 1시간, 한국 시간)이 들어갑니다.

- 보내기 전에 오늘 남은 메일 한도(`MailApp.getRemainingDailyQuota`)를 봅니다. 한도가 없으면 메일만 건너뛰고 주문은 받습니다. 그 줄 `처리 기록`에 '입금 안내 메일 못 보냄(오늘 메일 한도 없음, 화면 안내만)'이 남습니다. 주문 화면에 같은 입금 안내가 나오므로 입금은 할 수 있습니다.
- 주문 화면의 결과 칸에도 같은 입금 기한이 나옵니다.

### 2-1-1. 입금 기한(주문 뒤 1시간)

- 주문이 들어오면 `입금 기한` 칸(맨 뒤)에 주문 시각 + 1시간을 적습니다. 바꾸려면 `Ebook.gs`의 `PAY_WINDOW_MS`와 홈페이지 `src/lib/ebooks.ts`의 `payWindowMs`를 함께 고칩니다.
- **10분 여유**: 자동 취소는 `입금 기한` + 10분이 지난 뒤에 합니다(`PAY_GRACE_MS` / `payGraceMs`). 입금 시각이 `입금 기한` + 10분 안이면 제때 입금으로 보고 보냅니다. 세무 봇이나 체크가 조금 늦어도 제때 낸 입금을 취소하지 않으려는 여유입니다. 주문 메일과 화면에는 1시간만 안내합니다.
- 5분마다 도는 정리가 `입금 기한` + 10분이 지났는데 `입금 확정`이 없는 `입금 대기` 줄을 `미입금 취소`로 바꾸고 `처리 기록`에 '미입금 취소 (입금 기한 11/3(화) 13:15 + 10분 지남)'처럼 남깁니다. `입금 시각`·`입금 확정`·`메모` 칸은 건드리지 않습니다.
- **기한 뒤 입금은 자동으로 보내지 않습니다.** 다음 경우는 `확인 필요`가 되고(`확인 필요 사유`·`처리 기록`에 적음) 세연쌤에게 확인 필요 메일이 갑니다.
  - `입금 대기` 줄에 `입금 확정`이 체크됐는데 `입금 시각`이 기한 + 10분 뒤인 경우
  - `입금 시각` 없이 기한 + 10분이 지난 뒤 `입금 확정`만 체크된 경우
  - `미입금 취소` 줄에 `입금 확정`이 체크되거나, [입금알림] 자동 확인(5번)에서 그 줄 입금자명으로 입금이 들어온 경우
- 확인한 뒤 보내려면 `다시 보내기`, 받지 않으려면 `취소`를 체크하고 환불합니다.
- 기한 + 10분 안에 들어온 입금(`입금 시각`이 기한 + 10분 전)은 체크가 늦어도 그대로 보냅니다.
- `입금 기한` 칸이 빈 줄(이 칸을 넣기 전 주문)은 기한 규칙을 쓰지 않습니다.
- `미입금 취소` 주문의 입금자명(이름+숫자)은 다음 주문에 다시 쓰지 않습니다. 기한 뒤 입금을 다른 주문과 헷갈리지 않게 하려는 것입니다.

### 2-2. 사업자 세무 관리 봇이 입금을 확인하는 방식(기본)

세연님 휴대폰 단축어가 카카오뱅크 입금 문자를 `사업자 세무 관리` 봇에 보내면, 봇이 `전자책 주문` 탭에서 `상태`가 `입금 대기`인 줄과 맞춰 봅니다.

- 봇은 머리글 이름으로 칸을 찾고 **`입금 시각`, `입금 확정`, `메모` 세 칸만** 씁니다. 다른 칸 이름·순서를 바꾸지 마세요.
- 봇이 `입금 확정`을 체크하면(시트 API 로 쓴 값이라 onEdit 는 돌지 않습니다) 5분마다 도는 정리가 PDF 를 보냅니다. 봇이 적은 `입금 시각`과 `메모`는 덮어쓰지 않습니다. `입금 확정`에 글자 `TRUE`가 들어가도 체크로 봅니다.
- 봇이 적은 `입금 시각`이 `입금 기한` + 10분 뒤면 보내지 않고 `확인 필요`로 둡니다(2-1-1). `입금 시각`은 날짜 값이나 `2026-11-03 12:07` 같은 글자(한국 시간)로 적으면 됩니다.
- 기한이 지나 `미입금 취소`가 된 줄은 `상태`가 `입금 대기`가 아니므로 봇이 맞추지 않습니다. 그 입금은 봇 `메모` 규칙대로 '확인 필요'로 남고, 세연님이 보고 처리합니다.
- 맞는 주문이 없거나 2건 이상이면 봇은 `메모`에 '확인 필요: …'만 적습니다. 그 줄은 보내지 않으므로 세연님이 보고 `입금 확정`을 체크합니다.
- 휴대폰이 꺼져 있거나 단축어가 실패하면 봇은 입금을 알 수 없습니다. 그때는 아래 2-3처럼 손으로 확인합니다.

### 2-3. 손으로 확인

새 주문이 들어오면 세연쌤 메일로 `[전자책] 새 주문 홍길동27 15,000원` 알림이 옵니다.

1. 카카오뱅크 앱에서 입금 내역을 봅니다.
2. `전자책 주문` 탭에서 **입금자명(이름+숫자 2자리)과 금액이 같은 줄**을 찾아 `입금 확정`을 체크합니다.
3. 체크하면 바로(늦어도 5분 안에) 주문자에게 PDF 메일이 나가고 `상태`가 `발송 완료`로 바뀝니다. `전자책 발송 기록`에 1줄이 생깁니다.
4. `현금영수증 발급 대기` 탭에 줄이 있으면 홈택스(또는 쓰시는 발급 방법)에서 그 번호로 발급하고 `발급함`을 체크합니다. `발급 시각`이 자동으로 적힙니다.
5. `[전자책] 확인 필요` 메일이 오면 아래 3번을 봅니다.

주문 페이지는 '입금 확인 후 30분 안에 보낸다'고 안내합니다. 손으로 확인할 때는 입금 알림을 본 뒤 30분 안에 체크해야 이 약속을 지킵니다.

## 3. 상태와 칸

| 상태 | 뜻 | 세연쌤이 할 일 |
| --- | --- | --- |
| 입금 대기 | 주문만 들어옴 | 입금을 보면 `입금 확정` 체크 |
| 발송 완료 | PDF 메일을 보냄 | 없음 |
| 미입금 취소 | 입금 기한(주문 뒤 1시간) + 10분까지 입금이 없어 자동 취소 | 없음. 기한 뒤 입금이 들어오면 `확인 필요`로 바뀝니다 |
| 확인 필요 | 자동으로 처리하지 못함 | `확인 필요 사유`를 보고 해결한 뒤 `다시 보내기` 체크(보냄) 또는 `취소` 체크 |
| 취소 | 보내지 않음 | 입금했다면 환불 |

- **확인 필요가 되는 경우**: 입금 기한 + 10분 뒤 입금, 미입금 취소 뒤 입금 확정(2-1-1), 입금 금액이 주문과 다름, 같은 입금자명 주문이 2건 이상, PDF 메일 발송 실패(파일 ID가 틀림, 주소가 틀림 등). `확인 필요` 줄은 자동으로 보내지 않습니다.
- **다시 보내기**: 체크하면 PDF를 다시 보내고 체크를 스스로 풉니다. 주문자가 '메일이 안 왔다'고 하면 이메일 주소를 고친 뒤 체크합니다. 입금 확정이 안 된 줄이면 입금 확정도 함께 체크됩니다.
- **취소**: 체크하면 `취소`가 되고 보내지 않습니다. 이미 보낸 줄도 `취소`로 바뀝니다(환불 기록용).
- 고치지 말아야 할 칸: `주문번호`, `상태`, `발송 시각`, `발송 횟수`, `처리 기록`, `입금 기한`. 메모는 `메모` 칸에 적습니다.
- 메일 한 통 첨부 한도는 18MB로 잡았습니다(Gmail 한도 25MB). 9권 합계는 약 9.4MB라 9권을 모두 사도 한 통으로 갑니다. 한도를 넘으면 여러 통으로 나눠 보냅니다. 파일 하나가 18MB를 넘으면 첨부하지 않고 `확인 필요`로 둡니다(그때는 드라이브에서 그 주문자 이메일로 직접 공유해 주세요).
- 하루 메일 한도: 일반 구글 계정은 Apps Script 메일 받는 사람이 하루 100명입니다. 주문 1건에 메일 2~3통(주문 접수, PDF, 세연쌤 알림)이 나갑니다. 하루 30건이 넘을 것 같으면 미리 알려 주세요. 주문 접수 메일과 새 주문 알림은 한도가 없으면 건너뜁니다(2-1).

## 4. 바꾸고 싶을 때

- 주문 접수 메일(입금 안내)을 보내지 않으려면 `SEND_ORDER_RECEIVED_MAIL: false`.
- 새 주문·확인 필요 알림 메일을 받지 않으려면 `NOTIFY_OWNER: false`.
- 고친 뒤에는 새 버전으로 배포합니다.

## 5. (선택, 기본 꺼짐) [입금알림] 메일 자동 확인

모의면접 `Code.gs`의 `AUTO_DEPOSIT_CHECK`를 켜면(`../mock-interview/README.md` 5번) 전자책 주문도 함께 확인합니다. 따로 켤 것은 없습니다.

- 입금 알림의 입금자명이 `입금 대기` 주문의 입금자명(이름+숫자 2자리)과 같은 주문이 **정확히 1건**이고 금액도 같으면 `입금 확정`을 자동으로 체크하고 PDF를 보냅니다.
- 입금자명이 `미입금 취소` 주문과 같으면(기한 뒤 입금) 보내지 않고 `확인 필요`로 둡니다.
- 입금자명은 맞는데 금액이 다르거나, 같은 입금자명 주문이 2건 이상이면 `확인 필요`로 두고 세연쌤에게 메일을 보냅니다.
- 모의면접 신청과 전자책 주문 양쪽에 맞으면 아무것도 체크하지 않고 `입금알림 기록`에 '손으로 확인'을 남깁니다.
- 입금자명이 다르면(숫자를 빼고 입금 등) 자동으로 맞추지 않습니다. 손으로 체크합니다.
